# Security model

## Trust boundaries

Lucid Auth assumes a trusted Cloudflare deployment, canonical HTTPS domain, D1 operators, configured Google OAuth client and mail delivery provider. Application origins that proxy session cookies become trusted parties. Restrict secrets and database access, require HTTPS, and keep authentication responses out of shared caches.

| Threat                                    | Design                                                                                                                                                                                                                                                                                                                                             |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Offline password guessing                 | Native Workers scrypt with per-password 32-byte CSPRNG salt, N=32768, r=8, p=3, and 32-byte output. Unknown users incur the same KDF work. Token generation and hashing use Web Crypto.                                                                                                                                                            |
| Account enumeration during auth           | Generic registration and recovery acceptance plus a matched login KDF path. Email syntax and throttling can produce separate errors. An organization manager can test whether a known address has a verified account via direct membership assignment.                                                                                             |
| Registration pre-hijacking                | Activation needs an email token and the original browser binding. A recovery link can activate a pending account only by setting a new password.                                                                                                                                                                                                   |
| Reset replay and stale credentials        | D1 atomically changes the password, expires tokens, removes enrolled passkeys and revokes active sessions. Password login verifies the credential hash again before issuing a session.                                                                                                                                                             |
| Session theft and fixation                | New random secrets per sign-in, SHA-256 hashes in D1, Secure host-only HttpOnly and SameSite=Lax browser cookies over HTTPS. Access expires after 15 minutes, refresh after 30 days from sign-in. One refresh wins each compare-and-swap. The immediately prior refresh hash can revoke its successor during logout and cannot sign in or refresh. |
| Cross-origin requests                     | Exact canonical Host/Origin checks on application requests and mutations, no API CORS policy, Lax cookies, restrictive CSP, and explicit fixed OAuth callback and redirects.                                                                                                                                                                       |
| OAuth code interception and login CSRF    | Hashed, expiring one-time state bound to an HttpOnly cookie, PKCE S256, nonce, fixed Google endpoints and RS256 signature/issuer/audience validation via JOSE. Existing sessions map Google by subject. No automatic email linking. New accounts require verified Gmail or Workspace email.                                                        |
| Passkey impersonation and replay          | SimpleWebAuthn verification of challenge, origin, RP ID, signature, authenticator flags and counters. Enrollment requires recent verified sign-in. A browser-bound challenge is consumed once. Credentials with a zero counter rely on one-use challenges for replay protection.                                                                   |
| Horizontal and vertical tenant escalation | Scope tenant queries, validate current role grants, enforce membership foreign keys and atomic mutation guards. Scoped organization session revocation has no effect on other organizations.                                                                                                                                                       |
| Brute force and traffic bursts            | Atomic D1 counters by Cloudflare client IP and, for password authentication actions, normalized email. Hostile distributed traffic still requires edge protection. Per-account throttles can temporarily deny login to that account.                                                                                                               |
| Accidental secret exposure                | Safe typed errors, redacted application logs, fragment-only email link secrets, and no provider access or refresh token persistence. Local-only demo mail is held temporarily in memory.                                                                                                                                                           |

## Roles and audit

| Capability                                         | Owner      | Admin                   | Member | Viewer |
| -------------------------------------------------- | ---------- | ----------------------- | ------ | ------ |
| Read organization, memberships, teams and overview | Yes        | Yes                     | Yes    | Yes    |
| Rename organization, manage teams                  | Yes        | Yes                     |        |        |
| Assign or remove member and viewer roles           | Yes        | Yes                     |        |        |
| Assign or remove owner and admin roles             | Yes        |                         |        |        |
| Read security events and sessions                  | Yes        | Yes                     |        |        |
| Revoke organization access for an active session   | Any member | Member or viewer target |        |        |

The final owner is protected during role changes, membership revocation and deletion. Admin sessions can view session times and sign-in events for current members of their organization because identities are shared. Global account session revocation remains an account-holder operation. Organization changes are recorded in the same transaction as the mutation. These D1 logs are operator-controlled records, retained for 90 days. Email addresses used as audit subjects can remain after deletion until retention cleanup.

Core automated tests use local D1 and Workerd. Google JWTs and authenticators are synthetic. Verify mail, hosted CPU budgets, Google redirects, physical passkeys, and edge protection on the actual deployment.
